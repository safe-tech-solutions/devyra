START

Metodologia

Substitua INTERFACE pela real (enp3s0, wlan0) e GATEWAY pelo roteador de ip route.

Ponto de partida — somente leitura
bash
ip -br addr
ip route
EscopoCausas são hipóteses, não diagnósticos. Muda com VM, container, VPN, Wi-Fi corporativo.

01

Interface e link físico

1A interface existe e tem link?
bash
ip -br link
ethtool INTERFACE
rfkill list
nmcli device status
dmesg | grep -iE 'eth|wlan|link'
  • Interface nem apareceDriver/hardware. Veja lspci e lsusb.
  • DOWNip link set INTERFACE up
  • NO-CARRIERCabo, switch, Wi-Fi não associado.
  • Link ativoVá para passo 2.
02

Endereço IP

2Tem o IPv4 esperado?
bash
ip -4 -br addr
nmcli device show INTERFACE
journalctl -u NetworkManager -e
  • Sem IP ou 169.254.x.xDHCP falhou. Veja servidor, VLAN.
  • IP/prefixo erradoMáscara errada esconde gateway.
  • IP corretoVá para passo 3.
Renovar DHCP
bash
nmcli con down "NOME" && nmcli con up "NOME"
03

Rota

3Existe rota para o destino?
bash
ip -4 route
ip -4 route get 1.1.1.1
ip rule show
  • Sem rota padrãoDHCP sem gateway.
  • Gateway inesperadoMétricas, VPN, bridge container.
  • Rota corretaVá para passo 4.
04

Gateway

4Gateway alcançável?
bash
ping -c 3 -W 2 GATEWAY
ip neigh show dev INTERFACE
  • Ping falha + ARP FAILEDL2: VLAN, isolamento, filtro MAC.
  • ARP OK, ping falhaICMP filtrado. Continue passo 5.
  • RespondeVá para passo 5.
05

Saída externa sem DNS

5Internet por IP puro?
bash
ping -c 3 -W 2 1.1.1.1
nc -vz -w 3 1.1.1.1 443
mtr -rw 1.1.1.1
ping -M do -s 1472 1.1.1.1
  • TCP OK, ping falhaICMP filtrado. Vá passo 6.
  • Ping OK, TCP falhaFiltro porta, proxy.
  • Ambos falhamFirewall, NAT, VPN, provedor.
  • Só pacote grande falhaMTU/MSS: PPPoE, VPN.
06

DNS

6Resolve nomes?
bash
getent ahosts example.com
dig example.com
dig @1.1.1.1 example.com
resolvectl status
cat /etc/resolv.conf
getent vs digdig ignora /etc/hosts. getent usa caminho real da app.
  • Sem respostaResolvedor, DNS VPN.
  • Só @1.1.1.1 funcionaResolvedor configurado errado.
  • Resolve certoVá passo 7.
07

Serviço e aplicação

7O serviço responde?

Cliente:

bash
curl -I --connect-timeout 5 --max-time 10 https://example.com
curl -v https://example.com
nc -vz -w 3 servidor 443

Servidor:

bash
ss -tulpn
systemctl status SERVICO
sudo nft list ruleset
sudo iptables -L -n -v
getenforce
  • TimeoutRota, firewall DROP, proxy.
  • Connection refusedServiço parado, bind 127.0.0.1.
  • Erro TLSRelógio, certificado, MITM.
  • HTTP 4xx/5xxRede OK, problema app.
LAB

Análise profunda

bash
sudo tcpdump -i INTERFACE -nn host 1.1.1.1
sudo tcpdump -i INTERFACE -nn port 443
sudo tcpdump -i INTERFACE -nn -w captura.pcap
Dica de ouroRode tcpdump nos dois lados ao mesmo tempo.

Cuidados

Não perca o SSHNunca reinicie rede via SSH sem console alternativa.
bash
sudo sh -c 'sleep 300 && reboot' &
Ping não é provaSem ping não significa fora do ar. Confirme com TCP.
Diagnóstico antes de mudarVerificação é leitura. Só mude após hipótese.
