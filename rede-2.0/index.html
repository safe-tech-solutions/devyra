Projeto 01

Monte um Lab de Troubleshooting de Redes no Linux

Crie hosts Linux isolados com namespaces de rede e pares veth. Inspecione interfaces, rotas, tabelas ARP/neighbor, sockets e tráfego usando ip, ss, ping, traceroute e tcpdump.

01
Objetivo do Projeto
  • Configurar hosts Linux isolados usando namespaces de rede.
  • Conectá-los com pares veth.
  • Explorar o comportamento real de rede.
  • Praticar troubleshooting com ferramentas de produção.
O Que Você Vai Construir
  • 3 hosts Linux isolados (namespaces)
  • Rede virtual com pares veth
  • Endereçamento IP e roteamento
  • Teste de conectividade e falhas
  • Captura e análise de tráfego
  • Investigação de ARP, rotas e sockets
Ferramentas Utilizadas
ip (iproute2) ss ping traceroute tcpdump nsenter wireshark (opcional)
Topologia do Lab
ns1 (10.10.1.1/24) ns-router (10.10.1.254/24 · 10.10.2.254/24) ns2 (10.10.2.1/24) App / Cliente ←──veth1──→ Roteador Linux (IP Forwarding habilitado) ←──veth2──→ App / Servidor
1Criar Namespaces de Rede
sudo ip netns add ns1 sudo ip netns add ns2 sudo ip netns add ns-router
2Criar Pares Veth
sudo ip link add veth1 type veth \ peer name veth1-r sudo ip link add veth2 type veth \ peer name veth2-r
3Mover Interfaces para Namespaces
sudo ip link set veth1 netns ns1 sudo ip link set veth1-r netns ns-router sudo ip link set veth2 netns ns2 sudo ip link set veth2-r netns ns-router
4Configurar Endereços IP
sudo ip netns exec ns1 ip addr add \ 10.10.1.1/24 dev veth1 sudo ip netns exec ns1 ip link set veth1 up sudo ip netns exec ns1 ip route add \ default via 10.10.1.254
5Habilitar IP Forwarding (Roteador)
sudo ip netns exec ns-router \ sysctl -w net.ipv4.ip_forward=1 # Adicionar IPs ao roteador sudo ip netns exec ns-router ip addr add \ 10.10.1.254/24 dev veth1-r sudo ip netns exec ns-router ip addr add \ 10.10.2.254/24 dev veth2-r
6Testar Conectividade
sudo ip netns exec ns1 ping 10.10.2.1 sudo ip netns exec ns1 traceroute 10.10.2.1 sudo ip netns exec ns2 ping 10.10.1.1
7Inspecionar Estado da Rede
sudo ip netns exec ns1 ip a sudo ip netns exec ns1 ip r sudo ip netns exec ns1 ip neigh sudo ip netns exec ns1 ss -tunap
8Capturar e Analisar Tráfego
sudo ip netns exec ns-router tcpdump -i any sudo ip netns exec ns1 tcpdump -i veth1 # Gerar tráfego em outro terminal: sudo ip netns exec ns1 ping 10.10.2.1
9Experimentar e Quebrar Coisas
  • Remover uma rota e observar a falha
  • Alterar MTU e observar problemas de pacotes
  • Bloquear tráfego com iptables
  • Observar comportamento do cache ARP
  • Analisar handshakes e resets TCP
🔑 Conclusão Chave

Problemas de rede são mais fáceis de resolver quando você consegue reproduzi-los.
