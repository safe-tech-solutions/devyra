01

Introdução ao Linux

O que é o Linux?

O Linux é um kernel de sistema operacional de código aberto, semelhante ao Unix, criado por Linus Torvalds em 1991. Ele gerencia hardware e recursos. Combinado com ferramentas, bibliotecas e aplicativos, torna-se um Sistema Operacional completo.

Por que o Linux domina Servidores e Nuvem?

  • Código Aberto e Gratuito: Sem custos de licença, impulsionado pela comunidade.
  • Estável e Confiável: Construído para manter alta disponibilidade em sistemas de longa execução.
  • Seguro por Design: Forte modelo de permissões e comunidade de segurança ativa.
  • Alto Desempenho: Uso de recursos leve e eficiente.
  • Nativo em Nuvem: Impulsiona contêineres, Kubernetes, DevOps e microsserviços.
  • Padrão da Indústria: Utilizado pelos principais provedores de nuvem e data centers do mundo.

Principais Distribuições Linux

  • Ubuntu: Amigável, excelente suporte da comunidade. Popular para servidores e desktops.
  • Rocky / AlmaLinux: Nível empresarial, estáveis e prontas para produção.
  • Red Hat Enterprise Linux (RHEL): Suporte empresarial e alta confiabilidade.
  • Debian: Muito estável, seguro e amplamente utilizado.
  • Arch Linux: Leve, rolling release para usuários avançados.

Sistema de Arquivos Linux

Tudo no Linux é um arquivo, inclusive dispositivos, processos e conexões de rede. O sistema organiza tudo em uma única árvore hierárquica, começando a partir da raiz /.

DiretórioPropósitoExemplos de Produção
/etcArquivos de configuração do sistema e softwares instalados./etc/nginx/nginx.conf, /etc/ssh/sshd_config
/varDados variáveis que mudam durante a operação (logs, caches, bancos de dados)./var/log/syslog, /var/lib/mysql
/homeDiretórios locais para usuários comuns./home/ubuntu/, /home/deploy/app/
/usrProgramas, utilitários e bibliotecas do sistema./usr/bin, /usr/lib
/optSoftwares de terceiros instalados por administradores./opt/docker/, /opt/jdk/
/tmpArquivos temporários — limpos na reinicialização./tmp/app.sock, /tmp/upload/
03

Navegando no Linux

  • pwd — Mostra o diretório de trabalho atual.
  • cd /var/log — Altera entre diretórios.
  • ls -lah — Lista com detalhes completos e arquivos ocultos.
  • tree -L 2 — Exibe estrutura em formato de árvore.
  • find /var/log -name "*.log" — Pesquisa por nome, tipo e data.
  • locate nginx.conf — Consulta rápida via banco de dados indexado.
bash
$ pwd
/home/devops
$ ls -lah /var/log
$ find /etc -name "*.conf" -type f
$ cd -    # retorna ao diretório anterior
04

Trabalhando com Arquivos e Diretórios

  • touch file.txt — Cria um arquivo vazio ou atualiza o timestamp.
  • mkdir -p /opt/app/logs — Cria diretórios com caminhos aninhados.
  • cp -r /etc/nginx /backup/ — Copia arquivos e diretórios recursivamente.
  • mv oldname.txt newname.txt — Move ou renomeia.
  • rm -r olddir/ — Remove diretório e seu conteúdo.
  • ln -s /var/log/app.log app.log — Cria link simbólico.
Atenção: Sempre confira o caminho antes de executar rm ou mv em produção. Um rm -rf / acidental pode destruir o sistema.
05

Visualizando e Editando Arquivos

  • cat /etc/hosts — Exibe o conteúdo completo (ideal para arquivos pequenos).
  • less /var/log/syslog — Rola para cima e para baixo em arquivos grandes.
  • head -n 20 app.log / tail -n 50 app.log — Primeiras ou últimas linhas.
  • tail -f /var/log/nginx/access.log — Monitora logs em tempo real.
  • nano / vim — Editores de texto para configurações e scripts.
vim — atalhos essenciais

:w       → salvar

:wq      → salvar e sair

06

Permissões no Linux

Permissões protegem o sistema através de três entidades: Usuário (owner), Grupo e Outros, usando r (leitura), w (escrita) e x (execução).

bash
$ chmod 755 script.sh    # rwxr-xr-x
$ chmod u+x script.sh   # adiciona execução ao owner
$ chown -R user:group /opt/app
$ chgrp -R webteam /var/www
Segurança: Evite chmod 777. Use menor privilégio. Prefira grupos para compartilhar acesso entre serviços.
07

Usuários e Grupos

O Linux é um sistema multiusuário. O gerenciamento adequado garante o Princípio do Menor Privilégio (PoLP) — cada processo recebe somente o acesso que precisa.

bash
$ sudo useradd -m alice         # cria usuário com home
$ sudo passwd alice             # define senha
$ sudo usermod -aG devops alice # adiciona ao grupo
$ sudo groupadd devops
$ groups alice                  # lista grupos do usuário
Boas práticas: Edite /etc/sudoers sempre com visudo, nunca com editor comum. Erros nesse arquivo podem bloquear o acesso root.
08

Processos

Um processo é a instância de um programa em execução, identificado por um PID (Process ID).

bash
$ ps aux                # fotografia de todos os processos
$ top / htop            # monitoramento em tempo real
$ pgrep -l nginx        # localiza por nome
$ kill 1234             # SIGTERM — finalização suave
$ kill -9 1234          # SIGKILL — força bruta
$ killall nginx
Boas práticas: Sempre tente SIGTERM antes de SIGKILL. Confirme o PID e entenda o que o processo faz antes de encerrar.
09

Serviços do Sistema (systemd)

O systemd gerencia o ciclo de vida dos serviços no Linux moderno.

bash
$ sudo systemctl start nginx    # inicia o serviço
$ sudo systemctl stop nginx     # para o serviço
$ sudo systemctl restart nginx  # reinicia
$ sudo systemctl reload nginx   # recarrega config sem derrubar
$ sudo systemctl enable nginx   # habilita no boot
$ systemctl status nginx        # status atual
$ sudo journalctl -u nginx -f   # logs em tempo real
10

Logs

Os logs contam a história do seu sistema. Saber lê-los é a habilidade mais importante de um sysadmin.

bash
$ journalctl -xe              # logs recentes com contexto
$ journalctl -u nginx -f      # logs de serviço em tempo real
$ tail -f /var/log/auth.log   # autenticações
$ dmesg -T | less             # mensagens do kernel
$ grep -i error /var/log/syslog | tail -50
Fluxo: Identifique → encontre o log certo → leia o período → filtre → analise → aja → valide. Use logrotate para rotação e retenção.

SSH (Secure Shell)

Acesso remoto seguro e criptografado. Em produção, use sempre autenticação por chave — nunca senha.

bash
$ ssh-keygen -t ed25519              # gera par de chaves
$ ssh-copy-id usuario@servidor       # copia chave pública
$ ssh -p 2222 usuario@servidor       # porta customizada
$ scp arquivo.tar.gz user@host:/tmp
Hardening: Desative PasswordAuthentication yes no /etc/ssh/sshd_config, use ed25519 e restrinja IPs com AllowUsers.

Fundamentos de Bash Scripting

#!/bin/bash
# Script de Exemplo Devyra
set -euo pipefail  # sai imediatamente em caso de erro

SERVICO="nginx"

if systemctl is-active --quiet "$SERVICO"; then
    echo "✓ $SERVICO está rodando."
else
    echo "⚠ ALERTA: $SERVICO inativo. Reiniciando..."
    sudo systemctl restart "$SERVICO"
fi
18

Tuning do Kernel com sysctl.d

sysctl ajusta parâmetros do kernel em tempo de execução, sem reinicialização. Persista as mudanças em /etc/sysctl.d/99-producao.conf.

/etc/sysctl.d/99-producao.conf
## Memória
vm.swappiness = 10
vm.dirty_ratio = 15

## Rede — TCP/IP
net.core.somaxconn = 65535
net.ipv4.tcp_tw_reuse = 1
net.ipv4.tcp_fin_timeout = 15
net.ipv4.tcp_syncookies = 1    # proteção SYN flood

## Filesystem
fs.file-max = 2097152
bash — aplicar
$ sudo sysctl -w vm.swappiness=10  # temporário
$ sudo sysctl --system             # aplica todos os *.conf

Troubleshooting no Linux

Abordagem sistemática para identificar, isolar e resolver incidentes de produção:

  1. Observar / Identificar: Qual é o sintoma exato e quem está sendo afetado?
  2. Coletar Informações: Métricas, status de serviços e logs (journalctl, /var/log/).
  3. Analisar e Hipotetizar: Encontre padrões e isole o escopo do problema.
  4. Testar e Resolver: Aplique a correção e valide a integridade do ambiente.
ÁreaFerramentas
CPUtop, htop, mpstat, sar
Memóriafree, vmstat, dmesg | grep oom
Discodf, du, iostat
Serviçossystemctl, journalctl
Redeping, ss, traceroute, dig
Kerneldmesg, sysctl, /proc/
20

Erros Comuns em Produção

  • Executar tarefas como Root: Aumenta drasticamente o raio de impacto de falhas acidentais. Use sudo com contas específicas.
  • Permissões incorretas: Podem derrubar aplicações ou expor dados sensíveis.
  • Ignorar logs: Oculta avisos preventivos até que uma indisponibilidade grave ocorra.
  • Backups não testados: Um backup nunca validado para restauração é um backup inútil.
  • Falta de plano de rollback: Nunca faça alterações em produção sem uma via segura de reversão.

Mini Projeto — Servidor NGINX Seguro

bash — setup completo
$ ssh ubuntu@server_ip
$ sudo adduser devops
$ sudo usermod -aG sudo devops
$ sudo apt update && sudo apt install -y nginx

# Tuning de produção
$ sudo tee /etc/sysctl.d/99-nginx.conf <<'EOF'
net.core.somaxconn = 65535
net.ipv4.tcp_tw_reuse = 1
fs.file-max = 2097152
EOF
$ sudo sysctl --system

$ sudo systemctl enable --now nginx
$ sudo ufw allow 80/tcp
$ sudo ufw allow 443/tcp
$ tail -f /var/log/nginx/access.log
Próximos passos: configure firewall (ufw/nftables), implemente logrotate, ative fail2ban e automatize backups com scripts Bash versionados no Git.
